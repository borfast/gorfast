# `crypt` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `crypt`: a versioned envelope over AES-256-GCM and XChaCha20-Poly1305 with a rotating keyring, a `Sealed` column type, public conformance suites, and a key generator.

**Architecture:** `crypt` is a primitive package (doctrine rule 1). Its non-test code uses only the standard library and `golang.org/x/crypto`. `Keyring` implements `Encryptor`; `Sealed` only carries bytes and moves them through `database/sql`. Portable behaviour is tested by `crypt/crypttest`; format behaviour by tests inside `crypt`.

**Tech Stack:** Go 1.27; `crypto/aes`, `crypto/cipher`, `crypto/hmac`, `crypto/sha256`; `golang.org/x/crypto/chacha20poly1305` v0.57.0; tests on SQLite (modernc) and Postgres through `internal/testdb`.

**Spec:** `docs/superpowers/specs/2026-10-02-crypt-design.md`. "§n" below means a section of it. Read it before any task.

## Decisions this plan adds to the spec

The spec leaves these open. Each is pinned by a test in the task named.

- `IsZero` means SQL `NULL` only (`b == nil`). `FromCiphertext([]byte{})` and an empty non-NULL column give a non-zero `Sealed` that fails to open (Tasks 1, 8). Correction: the prototype hid that modernc returns an empty BLOB as a nil `[]byte`; `Scan` handles it (commit `9c0b1fd`).
- `Key` holds a pointer to unexported data, so `fmt` prints only an address when a `Key` sits in an unexported field of another struct (Task 2).
- `Key.String()` writes the key ID as 16 lowercase hex digits: `xchacha20poly1305:3f9a0c1d2e4b5a69` (Task 2).
- `ParseKey` trims surrounding whitespace, so `"a, b"` and a trailing newline work. Algorithm names match exactly, lowercase (Task 2).
- `ErrUnknownKey` is wrapped with the key ID in hex, so an operator can find the archived key (§6, "Retiring a key"). `ErrCannotOpen` is returned bare (Task 3).
- `Open` returns `nil` plaintext with every error, and `Encryptor` implementations must be safe for concurrent use. Both are part of `RunEncryptor` (Task 6).
- `RunKeySource` requires a source that supplies keys `Load` accepts (Task 6).
- The fuzz test also asserts every `Open` error is one of the two sentinels. It still never asserts that a value opens (Task 4).
- `testdata/vectors.json` is written by its test only when missing, never overwritten. Regenerating it means deleting it, which shows in the diff (Task 4).
- `newkey` holds its own two-entry map from flag value to `Algorithm`, because §3 exports no name lookup (Task 7).

## Review Focus

1. **A model struct reused across rows.** Scanning `NULL` into a `Sealed` that holds the previous row's value must make it zero, not keep the old ciphertext. Tests: Task 1 `TestScanNullResets`, Task 8 `TestSealedColumn`.
2. **An empty non-NULL column.** A zero-length `BYTEA`/`BLOB` must scan to a non-zero `Sealed` that fails to open, so a resealing loop cannot mistake damaged data for an intentional `NULL` (§6, §8). Tests: Task 1 `TestEmptyIsNotZero`, Task 8 `TestSealedColumn`.
3. **Pasted key lists.** `"spec1, spec2"`, a trailing newline, or a trailing comma. Whitespace is accepted; an empty entry is refused at startup, naming its 1-based position; no error contains material. Tests: Task 2 `TestParseKeyTrimsWhitespace`, Task 5 `TestLoadSplitsTheDocumentedWay`, `TestLoadRefuses`.
4. **Keys printed in logs.** A `Key` in an unexported config field, a `[]Key`, or a `*Keyring` printed with `%v`, `%+v` or `%#v` reveals no material. Tests: Task 2 `TestKeyNeverPrintsMaterial`, Task 3 `TestKeyringNeverPrintsMaterial`.
5. **One keyring shared by concurrent handlers.** `Seal` and `Open` from many goroutines must be race-free. Test: Task 6 `ConcurrentUse`, run with `-race`.

- [x] **Step 4: Implement `crypt/keyring.go`**

- `NewKeyring` refuses the zero `Key` and duplicate key IDs, naming 1-based positions (1 is current); it may print `Key.String()`. It builds one AEAD per key once.
- `Seal` writes header `{0x01, alg, id}`, reads the nonce with `io.ReadFull(k.rand, nonce)`, authenticates `header || binding`, and returns `header || nonce || ciphertext+tag`.
- `Open` checks in this order (§5 rules 2 and 4), returning `nil` plaintext on each failure: length below 10, version not 1, unknown algorithm, all `ErrCannotOpen`; key ID not held, `fmt.Errorf("%w (key ID %x)", ErrUnknownKey, id)`; header algorithm differs from the key's, length below header + nonce + 16, or AEAD failure, all `ErrCannotOpen`.
- `Open` and `Reseal` share one unexported function that also returns which key opened the value. `Reseal` returns `s` itself with `false` when that key is current, else a fresh `Seal` with `true`.
- `NeedsReseal` is true only when the length is at least 10, the version is 1, the algorithm is known, the key is held and retired, and the header algorithm matches the key's.
